## Maintenance and delivery

Migration038 installs a durable job request table and settings revision lock. Agent run-now is a reviewed enqueue; execution happens after commit by the existing external cron endpoint. Native run-now uses the same request service and dispatcher. A database-specific MySQL advisory lock prevents overlaps. Tests hold the lock from a second PDO connection and verify a queued request survives until release. Dispatch rechecks principal/connection/credential and scope, cancels revoked requesters, recovers interrupted workers without repeating completed steps, bounds work and projects fixed error codes. Tasks include retention, reminders, durable deliveries, OAuth, customer-access, media, webhook and outbox cleanup.

Reminder scanning respects historical tenant-local scheduled times, enqueues a unique logical intent, and excludes already-queued reminders so retries cannot starve new work. Delivery rechecks customer anonymization, current tenant, current booking status and start time. Outbox attempts retain the same Message-ID. Test sink verifies failure followed by success yields one logical outbox record and identical message IDs. SMTP/provider delivery remains **at least once**, because an uncertain external acknowledgment can be retried. No exactly-once email claim is made. Resend's official24-hour idempotency key requires an identical payload; current fresh access-link rendering makes blindly adding that key incorrect: https://resend.com/docs/dashboard/emails/idempotency-keys.
