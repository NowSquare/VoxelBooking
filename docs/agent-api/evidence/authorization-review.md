# Independent catalog, business and system review

Reviewer: protocol/contracts agent, independent of the catalog/business/system implementation owner. Reviewed the shared catalog, business, team, application and system services, operation definitions, human adapters and maintenance coordinator, with emphasis on delegated authority, current role, business boundaries, transactions, review binding and inventory preservation.

The following actionable findings were reported, reproduced as failing regression tests by the implementation owner, and fixed:

1. **Retained catalog actor could outlive credential rotation/revocation in direct shared-service calls.** The transport executor refreshed the connection, but `CatalogService::guard` only resolved the principal. The guard now refreshes the credential and connection before checking current principal grants. Cursor binding also incorporates the refreshed identity/grants. Regression: `CatalogOperationsTest::testSharedCatalogRejectsRetainedActorAfterCredentialRotationAndRevocation`.
2. **Capacity edits/deletion did not preserve occupied windows and reserved capacity.** The service now checks exact capacity-slot IDs and legacy bookings with a null slot ID matched by weekday/time. Pending, confirmed and legacy rescheduled bookings without replacements reserve inventory; replaced origins do not. Preview and commit reject deletion, moved windows and capacity below the occupied total. Events received the corresponding legacy-rescheduled/delete-preview correction. Regression: `CatalogOperationsTest::testCapacityEditsAndDeletePreserveOccupiedWindowsIncludingLegacyReservations`.
3. **Authorization reads before a waiting domain lock could preserve an obsolete MySQL snapshot.** A deterministic concurrent-version regression reproduced two successful writers where one stale-version conflict was required. Shared transactions now use READ COMMITTED; inventory/business locks and receipt uniqueness remain. Regressions: `CatalogOperationsTest::testEarlierAuthorizationReadCannotHideACommittedCatalogVersion` and `SystemOperationsTest::testEarlierAuthorizationReadCannotHideCommittedSystemSettings`.
4. **A writer waiting for a business lock needed to recheck current authority after acquiring it.** Catalog, team, business, application review and system-settings services now revalidate principal, role, credential and grant at the locked write boundary. Regression: `CatalogOperationsTest::testWaitingCatalogTeamAndSettingsWritersRecheckIdentity`.

The owner recorded the initial two failing regressions in `/tmp/voxelbooking-agent-catalog-review-red.log`. The subsequent full reviewed run recorded all 23 catalog tests passing (full-run log `/tmp/voxelbooking-agent-full-reviewed.log`). The final focused reviewed-domain run passed **56 tests and 179 assertions** on PHP 8.5.10/MySQL 8.4.11, with no warnings or deprecations (`/tmp/voxelbooking-agent-reviewed-domains-green.log`). The reviewer inspected the corrected source and added separate real-operation success-contract, review, idempotency and HTTP/MCP parity tests in `OperationContractCoverageTest` (9 tests, 634 assertions).

Other reviewed boundaries: business/team queries constrain current granted business IDs; team access changes serialize on the business lock and preserve the last active owner; application review changes request status without implicit provisioning; new business creation does not expand an existing connection grant; system settings expose only documented nonsecret fields; job requests commit before dispatch and reauthorize the requester; the dispatcher uses an installation lock while processing maintenance. No further confirmed finding was left open in these reviewed paths.

This is a scoped code review and regression record. It does not replace the separate booking concurrency, customer capability, OAuth, migration, external delivery and complete release-ledger checks.

## Connection activity follow-up

The protocol reviewer independently inspected `ConnectionState::browserActivity`, `ConnectionsController::activity`, the activity template and index links after their addition. No blocking finding remained. The browser service refreshes the current session principal, requires a staff browser session, selects the connection by both principal type and ID, and filters audit rows by actor, connection and current business access. A revoked or expired connection's retained history is available only to its current owning person. The opaque cursor binds the actor and connection; every page reapplies current business filtering.

The controller resolves business names only from filtered rows. The template escapes names, titles, references, dates and URL components, excludes raw audit details, and uses native keyboard-accessible disclosures for receipt/request references. Responses use the application's private-cache protections. `SettingsIdentityOperationsTest::testBrowserActivityRetainsOwnRevokedHistoryAndBindsPagination` covers revoked-history retention, pagination, cross-connection cursors, cross-person denial and credential exclusion.

The documentation was clarified to describe saved/committed operations: reads and unsuccessful requests do not create operation receipts and are not included in this activity view. This avoids implying a complete request log.

The final focused settings/identity/activity run passed **21 tests and 242 assertions**, with no warnings or deprecations. This includes the retained-history and cross-person/cursor regression described above.
